# 이름 쓰기 보상과 포획 게임

## 실행과 사용

Node 24, Python 3 환경에서 저장소 루트에서 `npm start`를 실행합니다. 추가 npm 의존성이나 빌드 과정은 없습니다.

1. **이름 써보기**에서 연습을 시작합니다.
2. 기존의 **다음 포켓몬 / 마지막 문제 완료** 버튼으로 이름 하나를 완료합니다. 글씨의 정확성이나 획순은 판정하지 않지만, 보이는 획이 없는 빈 화면에서는 완료와 볼 지급을 막습니다. 연한 글자 가이드, 흰 지우개 자국, 전부 지운/되돌린 화면은 쓴 것으로 보지 않습니다. 쓰기·지우기·PNG 저장 자체는 완료가 아닙니다.
3. 저장이 끝나면 보상 알림 패널 없이 다음 문제로 넘어갑니다. 볼은 기존처럼 지급하며 보유 수량은 포획 화면에서 확인합니다. 쓰기 도구 옆 **포켓몬 잡으러 가기**로 이동할 수 있습니다.
4. 포획 화면 아래 공에서 위로 스와이프합니다. 좌우 방향과 힘에 따라 궤적이 달라지며 빗나가도 볼은 소비됩니다. 종류 선택은 키보드로도 가능합니다.
5. 성공하면 **잡은 포켓몬** 목록에 최초·최근 포획 날짜와 횟수가 남습니다. 실패·포획과 관계없이 쓰기 완료 기록은 유지됩니다. 결과 연출 후 실패하면 같은 대상에게 다음 볼을 바로 던질 수 있고, 성공하면 다음 대상이 자동으로 나타납니다. 후보가 여러 종이면 방금 잡은 종은 다음 선택에서 제외합니다. 볼이 없으면 다음 공은 표시하지 않고 쓰기로 안내합니다.

볼이 없으면 이름 쓰기로 안내합니다. 소리는 사용하지 않으며 모든 결과는 화면과 `aria-live`로 전달합니다. 감소된 모션에서는 대상·조준 원을 고정하고 연출을 짧게 합니다. 작은 가로 화면은 전용 2열 포획 화면을 사용하며 돌아가기 버튼으로 나옵니다.

## 변경 위치

- `index.html`: 포획 메뉴·화면, 기존 쓰기 완료 연결, 진행·획 이미지 저장/복구.
- `src/modules/capture/rules.js`: 보상 추첨, 스와이프·궤적·이동·충돌, 조준 등급과 확률. 초기 튜닝값의 기준 파일.
- `store.js`: IndexedDB 트랜잭션, 완료·보상 원장, 잔액, 투척·환불, 포획 목록. 기존 localStorage 데이터는 변경하지 않습니다.
- `engine.js`: 상태 전이, 포인터 입력, 장면 시간, Web Locks 소유권, 결과 연출·재시도.
- `sprites.js`, `fallback.svg`: API·이미지 타임아웃, 동시 요청 병합, 응답·성공 후보 캐시, 로드/디코딩 실패 폴백, 투명 영역 측정.
- `style.css`: 반응형 포획 UI. 기존 숲 배경을 장식으로 사용하며 충돌에는 사용하지 않습니다.

## 저장 규칙

학습자 프로필이 없어 `device-default` 한 명을 사용합니다. 저장 API는 학습자 키를 받아 구분할 수 있지만 프로필 선택 UI는 추가하지 않았습니다. 서버 동기화는 없습니다.

IndexedDB `pokestudy-capture-v1`의 `learners` 스토어에서 학습자 하나를 하나의 원자적 레코드로 저장합니다. 쓰기 세션·문제별 시도 ID·추첨값은 연습 시작 시 저장하며, 포인터 입력이 끝날 때 획 이미지를 저장합니다. 완료 버튼은 동일 트랜잭션에서 완료 기록, 보상 종류, 잔액, 다음 문제 진행을 확정합니다. 같은 시도 ID는 이미 저장된 보상을 반환합니다. 기능 추가 이전 학습에는 소급 지급하지 않습니다.

유효 투척은 차감과 투척 ID·선택 볼·난수를 함께 저장한 뒤 시작합니다. 첫 충돌/빗나감 결과, 조우의 명중 실패 횟수, 포획 목록을 한 번에 저장한 뒤 연출합니다. 확정된 결과와 포획 목록은 새로고침해도 유지되며, 성공한 조우는 자동으로 다음 조우로 넘어갑니다. 미결 투척만 소비한 종류로 한 번 환불하며 확정 결과와 환불은 상호 배타적입니다.

Web Locks의 `pokestudy-capture-device-default` 잠금은 열린 포획 화면 동안 유지합니다. 다른 탭은 투척·환불을 하지 못하고 안내를 표시합니다. 화면 이탈·페이지 종료 시 잠금을 놓고, 다음 소유자가 미결 투척을 복구합니다. BroadcastChannel로 다른 탭의 새 쓰기 보상을 알리고, 화면 복귀 시에도 잔액을 다시 읽습니다. IndexedDB 또는 Web Locks를 지원하지 않는 브라우저는 저장 없이 게임을 진행하지 않습니다. HTTPS 또는 localhost에서 실행해야 합니다. 브라우저 사이트 데이터 삭제 시 기록이 삭제됩니다.

## 초기값

보상 확률은 70/20/9/1%입니다. 일반 포켓몬의 기본 명중 포획률은 몬스터볼 65%, 슈퍼볼 75%, 하이퍼볼 85%로 조정했습니다. 기본 포획률은 일반/드문/희귀 65/60/45%이며 슈퍼볼 +10%p, 하이퍼볼 +20%p를 적용합니다. 등급·첫 조우·놓침 보정과 10~95% 제한은 유지합니다. 마스터볼도 빗나가면 소비되지만 명중 시 100% 성공합니다. 난수와 최종 확률이 같으면 실패합니다. 희귀도 없는 기존 학습 목록은 일반으로 취급합니다.

첫 정지 5초, 이후 3초 간격·0.55초 이동을 사용합니다. 조준 원 색은 나이스 구간의 파스텔 초록, 그레이트 구간의 파스텔 주황, 엑설런트 구간의 파스텔 빨강을 사용합니다. 등급 경계 직전 5% 구간에서 다음 색으로 연속 보간합니다. 감소된 모션은 정지 원 비율 60%(원 안 명중은 그레이트)를 사용합니다. 스와이프 문턱은 높이 6%이며 공 중심은 (0.5, 0.86)입니다. 충돌은 작은 시간 구간의 상대 이동 선분으로 검사해 낮은 프레임에서도 통과를 감지합니다. 조준 등급은 첫 접촉 시 공과 원의 겹침을 기준으로 계산합니다. 실제 이미지의 투명 여백을 측정해 표시 크기를 맞추며 몸통 판정 영역은 별도로 둡니다. 포켓몬 히트박스는 기존 가로·세로를 각각 30% 축소하여 플레이 영역 너비의 8.4% × 높이의 5.6%인 타원입니다(반지름 0.042/0.028). 공 크기는 52px로 유지하며 실제 공 중심의 충돌 타원은 각 반지름에 26px를 더합니다.

장면은 화면이 숨겨지면 멈추고 복귀 시 프레임 기준 시간을 초기화합니다. 조준 중 회전·화면 이탈·포인터 취소·멀티터치는 차감하지 않습니다. 저장 실패에는 재시도 버튼을 표시하고, 결과 재시도는 같은 투척 ID와 난수를 사용합니다.

## 검증

```sh
npm test
python tests/capture_browser.py
python tests/capture_sprites_browser.py
python tests/browser_smoke.py
```

Python 검사는 Playwright, Pillow, `/usr/bin/chromium`이 필요합니다. 새 포획 검사 두 개는 자체 임시 HTTP 서버를 띄웁니다. 기존 `browser_smoke.py`는 `npm start`가 필요합니다. 테스트의 API·스프라이트·난수는 fixture로 대체하며 제품 코드에 테스트 포켓몬을 저장하지 않습니다.

순수 로직 검사에는 보상/등급 경계, 방향·힘, 이동·선분 충돌, 확률·마스터볼을 포함합니다. 브라우저 검사는 실제 IndexedDB의 원자성·중복·학습자 분리·동시 차감·환불, 완료부터 포획까지 흐름, 재시도·응답 유실·저장 실패 주입, 새로고침과 탭 소유권, 터치 취소·회전, 작은 화면, 이미지 오류·캐시·타임아웃·늦은 응답을 검사합니다. 기존 회귀 검사는 비동기 저장 완료 후 다음 문제를 확인하도록 대기를 추가했습니다.

미확인: 실제 iPad Safari/Android의 터치 조작감, 실제 아이의 조작성, 라이브 PokéAPI 전체 응답·애니메이션 품질. 현재 환경의 `pokeapi.co` 접근은 네트워크 정책에 차단되므로 라이브 검증은 허용 설정 적용 후 별도 수행해야 합니다. 자동 브라우저 검사는 실제 기기 검증을 대체하지 않습니다.


## 획순 가이드

이름 쓰기에서 **획순 번호**가 기본으로 켜지며 연한 가이드에 글자별 1번부터 번호를 표시합니다. **획순 재생**은 초성→중성→종성 순서로 획을 진행 방향대로 그려 주고, **한 획씩 보기**는 한 번에 한 획을 표시합니다. **획순 크게 보기**에서 이름의 글자를 선택하면 해당 글자만 확대해 시작점·방향 화살표·번호를 볼 수 있습니다. 같은 위치에서 시작하는 획의 번호는 겹치지 않게 배치하고 선으로 시작점을 연결합니다. 재생 중 쓰기 화면을 떠나면 재생을 멈추고, 페이지가 숨겨지면 시간을 멈춥니다. 감소된 모션에서는 재생 버튼도 한 획씩 표시합니다.

숫자·영문·기호에는 획순을 임의 생성하지 않고 일반 글자 가이드를 표시합니다. **연한 글자 가이드**를 끄면 번호 가이드도 숨기며, **획순 번호**만 끄면 기존 글꼴로 돌아갑니다. 작품 PNG에는 현재 표시하는 번호 가이드와 실제 쓴 획을 저장합니다. 가이드 SVG는 쓰기 캔버스와 분리되어 있어 가이드나 애니메이션만으로 완료·볼 지급이 되지 않습니다. 기존의 빈 화면 방지 기준은 유지하며 글자 정확성·사용자가 그린 획순을 자동 판정하지 않습니다.

데이터는 MIT 라이선스의 [Hangul Writer 1.0.1](https://github.com/mirodn/hangul-writer)를 `src/vendor/hangul-writer/`에 포함했습니다. npm 배포 아카이브의 SHA-512 무결성을 검증했고 라이선스·저작권·원본 설명을 함께 보존했습니다. 런타임에는 외부 CDN이나 문자 데이터 요청을 하지 않습니다. 51개 자모와 현대 한글 11,172개 음절의 자모별 획순 및 음절 합성 기능을 사용합니다. 음절 모양은 자모에서 합성하므로 기존 글꼴과 다를 수 있습니다. ㅈ·ㅊ은 인쇄체 기준 3획·4획이며, 필기체 등 다른 교육 관행과 차이가 있을 수 있습니다. 데이터 출처·버전·무결성은 `src/vendor/hangul-writer/README.md`를 참고하세요.

검증: `npm test`의 자모 획수·방향, 포켓몬 이름 합성, 겹받침·복합모음 및 비한글 처리와 `python tests/handwriting_strokes_browser.py`의 번호·확대·순차 재생·한 획씩 보기·가이드 토글·PNG 저장·빈 화면 격리·화면 크기·이동·감소된 모션 검사를 사용합니다. 실제 아이의 학습 효과, 실기기 Safari/Android 조작감 및 교육 전문가의 전체 데이터 검수는 별도입니다.


## 펜 우선 입력과 이전 화면 갱신

`src/modules/handwriting/pen-input.js`가 쓰기·색칠 입력 모드를 공유합니다. `auto`는 펜 이벤트 관측 전 모든 입력을 허용하고, `pointerType === "pen"` 이벤트를 관측한 뒤 캔버스에는 펜만 허용합니다. `pen`은 관측 전부터 펜만 허용하며, `all`은 손가락·마우스를 다시 허용합니다. 선택 모드는 `pokestudy-drawing-input-mode` 키에 저장하지만 자동 감지 상태는 페이지 수명 동안만 유지합니다. JavaScript로 Apple Pencil의 연결·페어링 여부를 미리 감지하지 않습니다.

쓰기와 색칠의 `setupDrawing`은 활성 포인터 ID를 추적하여 다른 손가락의 이동/종료가 펜 획을 변경하거나 끝내지 못하게 합니다. 펜이 활성 손가락을 대체하면 그 손가락 획의 시작 전 이미지·되돌리기 기록으로 복구한 뒤 펜 획을 시작합니다. 차단 범위는 캔버스뿐이므로 일반 UI 조작은 손가락으로 할 수 있습니다. 입력 취소·회전·화면 이탈 시 활성 획을 취소합니다.

획순 버튼 자체가 없는 이전 HTML이 열린 경우 새 조회 조건의 링크 `/?v=20261110-pen-guide`로 다시 엽니다. 획순 CSS·모듈에도 갱신용 버전 조회 조건을 적용했습니다. 새 HTML의 `app-version` 메타 값은 `2026-11-10-pen-guide`입니다. 이는 기존에 열려 있는 문서를 자동 갱신하지 않으며, 이전 화면에서 새 링크로 이동하거나 새로고침해야 합니다. 브라우저 저장 데이터를 삭제할 필요는 없습니다.

검증: `tests/pen-input.test.js`의 모드별 정책과 `python tests/pen_input_browser.py`의 iPad 화면 크기 Chromium 검사로 펜 전환, 손바닥 자국 복구, 포인터 소유권, 차단·해제, 저장된 설정, 되돌리기, 일반 버튼 터치 및 색칠 공유를 확인합니다. 이 검사는 실제 iPad Safari/Apple Pencil의 하드웨어 판정을 대체하지 않습니다.
