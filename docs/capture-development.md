# 이름 쓰기 보상과 포획 게임

## 실행과 사용

Node 24, Python 3 환경에서 저장소 루트에서 `npm start`를 실행합니다. 추가 npm 의존성이나 빌드 과정은 없습니다.

1. **이름 써보기**에서 연습을 시작합니다.
2. 기존의 **다음 포켓몬 / 마지막 문제 완료** 버튼으로 이름 하나를 완료합니다. 기존 앱과 같이 글씨 인식이나 획수 판정은 하지 않습니다. 쓰기·지우기·PNG 저장 자체는 완료가 아닙니다.
3. 저장이 끝나면 볼 종류와 보유 수량을 표시합니다. **포켓몬 잡으러 가기** 또는 **계속 쓰기**를 선택합니다.
4. 포획 화면 아래 공에서 위로 스와이프합니다. 좌우 방향과 힘에 따라 궤적이 달라지며 빗나가도 볼은 소비됩니다. 종류 선택은 키보드로도 가능합니다.
5. 성공하면 **잡은 포켓몬** 목록에 최초·최근 포획 날짜와 횟수가 남습니다. 실패·포획과 관계없이 쓰기 완료 기록은 유지됩니다.

볼이 없으면 이름 쓰기로 안내합니다. 소리는 사용하지 않으며 모든 결과는 화면과 `aria-live`로 전달합니다. 감소된 모션에서는 대상·조준 원을 고정하고 연출을 짧게 합니다. 작은 가로 화면은 전용 2열 포획 화면을 사용하며 돌아가기 버튼으로 나옵니다.

## 변경 위치

- `index.html`: 포획 메뉴·화면, 기존 쓰기 완료 연결, 진행·획 이미지 저장/복구.
- `src/modules/capture/rules.js`: 보상 추첨, 스와이프·궤적·이동·충돌, 조준 등급과 확률. 초기 튜닝값의 기준 파일.
- `store.js`: IndexedDB 트랜잭션, 완료·보상 원장, 잔액, 투척·환불, 포획 목록. 기존 localStorage 데이터는 변경하지 않습니다.
- `engine.js`: 상태 전이, 포인터 입력, 장면 시간, Web Locks 소유권, 결과 연출·재시도.
- `sprites.js`, `fallback.svg`: API·이미지 타임아웃, 동시 요청 병합, 응답·성공 후보 캐시, 로드/디코딩 실패 폴백, 투명 영역 측정.
- `style.css`: 반응형 포획 UI. 기존 숲 배경을 장식으로 사용하며 충돌에는 사용하지 않습니다.

## 저장 규칙

학습자 프로필이 없어 `device-default` 한 명을 사용합니다. 저장 API는 학습자 키를 받아 구분할 수 있지만 프로필 선택 UI는 추가하지 않았습니다. 서버 동기화는 없습니다.

IndexedDB `pokestudy-capture-v1`의 `learners` 스토어에서 학습자 하나를 하나의 원자적 레코드로 저장합니다. 쓰기 세션·문제별 시도 ID·추첨값은 연습 시작 시 저장하며, 포인터 입력이 끝날 때 획 이미지를 저장합니다. 완료 버튼은 동일 트랜잭션에서 완료 기록, 보상 종류, 잔액, 다음 문제 진행을 확정합니다. 같은 시도 ID는 이미 저장된 보상을 반환합니다. 기능 추가 이전 학습에는 소급 지급하지 않습니다.

유효 투척은 차감과 투척 ID·선택 볼·난수를 함께 저장한 뒤 시작합니다. 첫 충돌/빗나감 결과, 조우의 명중 실패 횟수, 포획 목록을 한 번에 저장한 뒤 연출합니다. 확정된 결과는 새로고침해도 유지됩니다. 미결 투척만 소비한 종류로 한 번 환불하며 확정 결과와 환불은 상호 배타적입니다.

Web Locks의 `pokestudy-capture-device-default` 잠금은 열린 포획 화면 동안 유지합니다. 다른 탭은 투척·환불을 하지 못하고 안내를 표시합니다. 화면 이탈·페이지 종료 시 잠금을 놓고, 다음 소유자가 미결 투척을 복구합니다. BroadcastChannel로 다른 탭의 새 쓰기 보상을 알리고, 화면 복귀 시에도 잔액을 다시 읽습니다. IndexedDB 또는 Web Locks를 지원하지 않는 브라우저는 저장 없이 게임을 진행하지 않습니다. HTTPS 또는 localhost에서 실행해야 합니다. 브라우저 사이트 데이터 삭제 시 기록이 삭제됩니다.

## 초기값

의뢰서의 보상 확률(70/20/9/1%), 기본 포획률(75/60/45%), 볼·등급·첫 조우·놓침 보정과 10~95% 제한을 적용합니다. 마스터볼도 빗나가면 소비되지만 명중 시 100% 성공합니다. 난수와 최종 확률이 같으면 실패합니다. 희귀도 없는 기존 학습 목록은 일반으로 취급합니다.

첫 정지 5초, 이후 3초 간격·0.55초 이동을 사용합니다. 감소된 모션은 정지 원 비율 60%(원 안 명중은 그레이트)를 사용합니다. 스와이프 문턱은 높이 6%이며 공 중심은 (0.5, 0.86)입니다. 충돌은 작은 시간 구간의 상대 이동 선분으로 검사해 낮은 프레임에서도 통과를 감지합니다. 조준 등급은 첫 접촉 시 공과 원의 겹침을 기준으로 계산합니다. 실제 이미지의 투명 여백을 측정해 표시 크기를 맞추며 몸통 판정 영역은 별도로 둡니다.

장면은 화면이 숨겨지면 멈추고 복귀 시 프레임 기준 시간을 초기화합니다. 조준 중 회전·화면 이탈·포인터 취소·멀티터치는 차감하지 않습니다. 저장 실패에는 재시도 버튼을 표시하고, 결과 재시도는 같은 투척 ID와 난수를 사용합니다.

## 검증

```sh
npm test
python tests/capture_browser.py
python tests/capture_sprites_browser.py
python tests/browser_smoke.py
```

Python 검사는 Playwright, Pillow, `/usr/bin/chromium`이 필요합니다. 새 포획 검사 두 개는 자체 임시 HTTP 서버를 띄웁니다. 기존 `browser_smoke.py`는 `npm start`가 필요합니다. 테스트의 API·스프라이트·난수는 fixture로 대체하며 제품 코드에 테스트 포켓몬을 저장하지 않습니다.

순수 로직 검사에는 보상/등급 경계, 방향·힘, 이동·선분 충돌, 확률·마스터볼을 포함합니다. 브라우저 검사는 실제 IndexedDB의 원자성·중복·학습자 분리·동시 차감·환불, 완료부터 포획까지 흐름, 재시도·응답 유실·저장 실패 주입, 새로고침과 탭 소유권, 터치 취소·회전, 작은 화면, 이미지 오류·캐시·타임아웃·늦은 응답을 검사합니다. 기존 회귀 검사는 비동기 저장 완료 후 다음 문제를 확인하도록 대기를 추가했습니다.

미확인: 실제 iPad Safari/Android의 터치 조작감, 실제 아이의 조작성, 라이브 PokéAPI 전체 응답·애니메이션 품질. 현재 환경의 `pokeapi.co` 접근은 네트워크 정책에 차단되므로 라이브 검증은 허용 설정 적용 후 별도 수행해야 합니다. 자동 브라우저 검사는 실제 기기 검증을 대체하지 않습니다.
